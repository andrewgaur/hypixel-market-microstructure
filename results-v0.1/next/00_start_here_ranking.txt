START HERE: PROJECT PRIORITIES FOR A BEGINNER
===========================================
Ranking criteria, in order:
1. Correctness: would postponing this make your data or conclusions unreliable?
2. Dependencies: does this unlock several later tasks?
3. Calendar time: can it run in the background while you learn other things?
4. Learning value and manageable scope: can you get a small working result first?
Speed matters, but a fast analysis of incorrectly labeled prices is not progress.

Rank  Original README point                                      First milestone
----  --------------------------------------------------------   ---------------
1     Immutable raw data, cleaned Parquet, documented schema       Save one verified response
2     Retry/backoff, rate limits, logging, monitoring               Survive a fake outage
3     Several more weeks of data                                  Start a monitored pilot
4     Unit/integration tests with GitHub Actions                    Offline tests run on a push
5     CLI interface and reproducible environment                   Fresh install reproduces a run
6     Walk-forward validation, horizons, baselines, CIs, power      One honest baseline comparison
7     Cost/spread-aware backtest                                   A hand-checked trade ledger
8     Polished 4-6 page paper/report                               Frozen results tell one story

Read 01 through 08 in order. Every file contains its ranking, plain-language
concepts, small steps, examples, common mistakes, and a completion checkpoint.
The ranking is by the main work package, not a prohibition on useful overlap.

Before rank 1: verify which API array represents executable bids and asks and
which entries are the best prices. This is essential because the legacy collector
selected values that produce crossed quotes. See the first guide and the new
script's fixes document. Do not spend weeks extending that extraction unchanged.

Important overlap:
- Write a few extraction and OFI tests during rank 1. Rank 4 is the fuller suite
  and CI automation, not permission to postpone checking correctness.
- Create the local Python environment before running anything. Rank 5 is the
  full user interface, installation documentation, and reproducibility work.
- Start rank 3 once raw saving, correct extraction, basic tests, and recovery
  work. Finish Parquet conveniences while collection continues.
- Read rank 6 early enough to predeclare horizons and a future confirmation
  window. Do not wait until after seeing all results to design the experiment.

Beginner working method
-----------------------
Open PowerShell in the repository root. A command beginning "python" asks Python
to run a program; the path after it tells Python which file. A flag beginning
"--" supplies a setting. A virtual environment is a project-local Python setup;
using its full executable path selects the installed project dependencies.

This workspace now has .venv-analysis2. To inspect the new script:
  .\.venv-analysis2\Scripts\python.exe src\bz_ofi_analysis2.py --help
To run the offline regression tests:
  .\.venv-analysis2\Scripts\python.exe -m unittest discover -s tests -v
To audit the existing data without pretending its book mapping is verified:
  .\.venv-analysis2\Scripts\python.exe src\bz_ofi_analysis2.py

The last command may deliberately return an "Analysis blocked" message. Read
the output directory's run_summary.txt and data_quality.json. That is a useful
diagnostic result, not evidence that changing a flag will repair the dataset.
See analysis2_fixes_and_usage.txt for installation and verified-input commands.

For each new feature: make one small change, run a tiny known example, inspect
the output, and save your work in Git. A commit is a named checkpoint of file
changes. Run git status and inspect what you are committing; do not accidentally
commit a virtual environment or gigabytes of observations.

Scope of this delivery
----------------------
The eight files are implementation guides. The new analysis script implements
offline analysis corrections and several analysis upgrades. It does not secretly
implement a new collector, a full raw-data platform, a trading backtest, or a
finished research paper. The six CURRENT PROJECT ISSUES from all-next.txt are
mapped individually in analysis2_fixes_and_usage.txt, including issues that need
new observations or future collector changes instead of an offline code patch.

Your existing .gitignore ignores results/next/. The files exist locally, but Git
will not include them by default. That preference has been preserved. If you
later want these notes versioned, deliberately change that rule or explicitly
add the selected files. The old analysis and collector remain available.
